## 分开检查的质量问题

1. **提取**：另做三次独立 Candidate 提取，DeepSeek 7.474 s、Gemini 12.086 s、Kimi 29.647 s，全部通过校验。姓名、电话、邮箱、城市与教育信息符合原文，14 项明确列出的核心技能均保留。Gemini 额外保留原文的英语等级，不属凭空增加。这只核对上述字段，不证明所有经历细节提取完整。
2. **证据结构**：当前 Block 是 PDF 非空行。成功报告中的部分证据只显示半句话，单条引用不足以独立说明完整责任范围，需结合邻近原文核对。Gemini 单模型另一次诊断（10.342 s，不混入上表）仍失败：部分 quote 跨连续多行，但只引用一个 block_id，还有引用起始行不符。单行来源校验因此拒绝；不是据此断定模型完全不理解简历。
3. **未定位的失败**：DeepSeek 初次组合路线未保留未验证响应，因此不能确认具体是哪条字段或引用触发拒绝。另一次独立提取成功，不能反过来抹掉初次失败，也不能假称已修复。
4. **文字报告**：Kimi 的结构化判断正确区分 unknown，但评论把“未体现”写成“缺乏经验”，并强化了熟练程度；一个面试问题还预设了原文未确认的零停机目标。JSON 合法及字段来源校验不能证明生成评论无误。DeepSeek 单模型和 Gemini 模板对此缺项使用了“未提及/尚未体现”等表述。

## 结论与后续工程事项

此前合成回归集上组合路线更符合规则，这份真实长简历则同时出现单模型和组合路线失败，没有证据证明某种架构普遍更好。应分别报告字段提取、引用有效性、判定政策、报告文字、耗时及成本。

优先完善可验证的跨行/段落证据表示，并增加合成换行回归；不能简单放宽为“全文中出现即可”，否则会丢失出处约束。随后验证生成报告是否与结构化结论一致，尤其是 unknown、熟练程度和未证实前提。上述问题尚未修复，现阶段不应声称真实复杂简历已稳定支持。
