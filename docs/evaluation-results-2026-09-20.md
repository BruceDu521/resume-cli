# 真实模型评测：2026-09-20

> 历史记录：2026-09-21 已移除 Jev/组合模式，并修订跨行引用合同。本文数据与命令属于旧版本；当前用法见 README，不与新版本混算。

Gemini、DeepSeek 和 Jev 已接通。最终版本完成 96 次真实评分和 10 项功能检查。DeepSeek + Jev 更快、估算费用更低，适合作为优先尝试的评分路径；两家模型仍有公开字段遗漏，暂不设置全局默认生成供应商。OpenAI / Kimi 缺本任务 key，未调用，其完整基线效果尚未比较。

## 方法与范围

- 本地 Poppler 解析合成 PDF；没有上传用户真实简历或 PDF 文件。
- 12 个开发案例和 4 个补充案例，每条路径每案例重复 3 次，共 48 次/路径。
- Gemini `gemini-3.8-flash`、DeepSeek `deepseek-flash`，均接同一 `jev-1.13.0`、代码评分政策和本地模板报告。简历/JD 结构化并行，试验串行，按固定种子打乱顺序。
- 应用缓存不复用。每次单独保存结构化结果供检查；供应商 prompt 缓存按实际 usage 计量。
- 耗时为完整 CLI 进程 wall time；Jev 单阶段耗时为请求到完整响应，不是首 token 时间。
- 来源规则检查脚本配合逐项阅读结果；不是外部人工标注数据集。要求类别、状态、字段完整性分别检查，不将成功退出等同正确。
- 补充案例在 v5 首次评估后用于修正基本熟悉程度及来源上下文，故 v6 已属于回归集。`heldout.json` 是历史文件名，最终没有独立保留集。

## 内容质量与取舍

**匹配状态。** 这批输入中的明确否定、缺失信息、技能、生产职责、优先要求和重叠任期均得到符合检查规则的最终状态。两次 DeepSeek 将“Rust 服务开发经验”归为 experience，约定规则应为 skill；均为 unknown、整体 0 分，因此该样例没有分数差异，但混合 JD 的维度权重可能受分类影响，不能忽略。

**公开字段。** Gemini 在 `heldout-en-missing #2` 漏掉 skills；DeepSeek 在 `overlap #1`、`en-core #2`、`heldout-en-positive #2` 漏掉 skills。这些结果的工作/技能 facts 仍保留了匹配所需证据，因此评分状态通过不能证明 extract 完整。DeepSeek 还有一次把整句开发/部署经历放入 skills，信息存在但格式不够简洁。核对技术名时接受包含名称的描述，未把“Kubernetes deployment”错误算成 Kubernetes 遗漏。

**报告。** 中英文模板输出、缺口解释和面试问题均可读；两次额外 AI 报告保持了 65 分及“开发/学历满足、独立生产运维不符”的判断，未修改代码计算的分数。少量样例不能保证任意生成报告无错误。

**选择。** DeepSeek 本轮端到端中位延迟约低 31%，估算单份费用约低 75%；评分状态与 Gemini 接近，作为成本优先的评分路径有依据。但公开字段完整性尚不相同，两家都存在遗漏，当前继续要求显式选择 provider。完整性优先时可先尝试 Gemini，并检查提取结果。不能据此外推生产准确率、万人简历吞吐或复杂 PDF 的稳定性。

## 实测暴露的问题及已完成修复

1. 生成模型偶发返回 schema 元数据，或将 JD 引用改写为非原文。继续严格拒绝；最多从原始输入重新生成一次，每次费用和阶段独立记录。鉴权失败不走该纠正。
2. Jev 概率经两位小数舍入合计 1.01，浮点边界曾导致误拒绝。加入既定舍入容差的浮点余量，范围、总和及 choice 一致性仍验证。
3. Jev 的“状态”和“证据”是独立问题，可能出现非 unknown 却选不到证据。该项改为 unknown/0 分并标记需复核，不静默给分。
4. 过短引用可能丢失否定、期限或责任边界。验证后恢复完整来源行，并为已提取的技能/教育补齐缺少的原文证据；不声称这能修复公开字段遗漏。
5. 空 facts 拒绝评分，避免把结构化失败显示成候选人全部不符。较短的已知经历只支持部分匹配，不直接断言总年限不足；个人项目可以支持“基本熟悉”，但不自动证明专业生产经验。

以上修复都有离线回归测试。历史失败保留在本机独立目录：早期开发轮 22/24 成功，后续三轮为 64/72、71/72、72/72；最后一轮虽全部返回，仍发现过技能证据遗漏和个人项目低估，故进行了来源上下文修复和最终 v6 复测。不同版本的耗时与质量不混算。
