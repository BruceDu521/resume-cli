# 单模型收敛与跨行来源验证

## 实现变更

按用户决定移除 Jev、组合模式、额外报告请求及相关参数/环境变量。score 使用所选生成模型完成一次分析（校验失败最多一次纠正），统一使用 RESUME_AI_API_KEY。extract 的私有缓存保留，score 不使用缓存。

没有更换 Poppler 或重写 PDF 文本。旧单行证据合同与完整语义要求冲突；现在显式支持 block_id 到 end_block_id 的连续范围，最多16块，仍要求引文来自所声明范围且不可跳过中间文字。模型提示解释物理换行，并要求选择完整上下文。最终诊断返回固定领域错误，纠正请求接收该安全原因而不是未信任的前次输出。

## 限定真实验证

使用同一份已授权两页中文简历及此前冻结的虚构测试 JD，每路线每轮一次。输入和结果均不入库。没有调用 Jev 或 OpenAI。

v1 原始结果在 `.local/real-resume/single-only-v1/`；v2 在 `single-only-v2/`。v2 增加安全的具体字段定位及纠正反馈；Gemini 未再次调用，避免无必要重复。两个轮次不能合并为一个同版本质量或速度统计。DeepSeek v2 首次即成功，没有用到反馈，因此不能把成功归因于反馈改进。Kimi v2 使用了纠正，但少量样例也不足以证明稳定改善。

三条成功报告均83分，必需要求满足、未在简历体现的优先技能为unknown。实际输出包含跨行起止ID和完整范围原文；Gemini本次没有再因引用单行限制失败。跨行跨度已纳入离线正反例：正确连续范围、缺失末行、错误首行、倒序、不存在ID、跳行拼接、编造内容、跨度上限、跨行否定上下文以及幂等/不修改调用方。

报告措辞本轮描述“未找到记录/未体现/无相关证据”，没有把该缺项明确写成候选人不能使用该技能。仍不能仅凭来源字符串检查证明评价或面试问题完全准确；有些引用只覆盖复合要求的部分语义，需结合其他证据判断。

## 工程验证与限制

全部离线 Go race/单测与 vet 通过，总覆盖87.7%；删除完整 Jev 模块后分母不同，不能把覆盖率变化理解为同一代码回退。凭据解析4项Python离线测试通过，mock两个命令案例通过。所有单元测试不使用真实网络或凭据。

本轮 Dockerfile 重建被 Docker Hub 认证服务 EOF 阻断；已用既有本项目镜像和当前 Linux/arm64 二进制完成 parse/extract/score 三命令禁网运行验收。这不等于本轮 Dockerfile 成功重建。

跨行结构问题已修正并有成功实测，但真实模型输出仍有不稳定性；保留失败而非只展示最终成功。没有生产准确率、任意版面支持或高并发能力的结论。
