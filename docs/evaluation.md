# 模型评测计划

状态：已实现评测脚本及合成案例，mock 链路通过；真实模型尚未运行。最新约定：Jev 用于组合流程；Gemini / DeepSeek 必须比较内容质量与真实速度，接近时优先更便宜的 DeepSeek；OpenAI / Kimi 用作完整流程对照。

## 要回答的问题

1. Gemini 与 DeepSeek 哪个更准确地提取事实、工作经历、证据和 JD 要求？
2. 接入同一个 Jev 判断与报告流程后，提取差异会怎样影响最终结果？
3. 各自真实调用和端到端耗时是多少，失败与重试有什么差异？
4. 组合流程相比 OpenAI / Kimi 独立完成分析，质量、耗时和任务成本如何？

## 四条路径

| 路径 | 本地输入处理 | AI 工作 | 报告 |
| --- | --- | --- | --- |
| Gemini + Jev | 共用 Poppler 输出 | Gemini 整理 + Jev 判断 | 共用模板；另测可选表达 |
| DeepSeek + Jev | 共用 Poppler 输出 | DeepSeek 整理 + Jev 判断 | 与 Gemini 路径一致 |
| OpenAI 对照 | 相同本地解析文本 | 独立提取、判断、提供报告文字 | 统一公开 schema |
| Kimi K3 对照 | 相同本地解析文本 | 独立提取、判断、提供报告文字 | 统一公开 schema |

OpenAI 初始对照目标为 GPT-6 Astra，实际账号可访问性和模型配置须在执行前核实；若不可用，记录缺项，不静默替换。Kimi 目标为 K3。同一评分政策、可用原始证据和输出约束适用于所有路径。精确分数汇总由共用代码完成；高能力模型也不能随意更改权重。

对照覆盖完整 AI 职责，不受 Jev 结果影响；允许模型用自己的最小必要调用数完成任务，记录全部调用。共用的本地步骤并不使对照失去独立性。

## 样例及质量评价

testdata/evaluation/cases.json 已有 12 个合成案例，覆盖中文、英文、混合语言、多段教育、任职时间重叠、明确否定、缺失信息、JD 可选要求及指令性输入。多栏阅读顺序另有本地 PDF 基础测试，尚未纳入模型评测。

当前 12 个案例为开发集，尚未建立独立保留集。正式结论前须将调 prompt 的样例与保留样例分开，固定各自身份；不把在同一批样例反复调整后的结果描述成独立测试准确率。

- 提取：逐字段核对正确、遗漏、凭空增加；记录字段类型和缺失处理。
- 证据：引用是否存在、是否真正支持结论，不能只检查字符串出现。
- 要求整理：必需与优先是否混淆、是否漏要求。
- 匹配：满足/部分/不符/未体现是否正确，强弱匹配排序是否合理。
- 报告：分数与文字是否一致，面试问题是否针对缺口或重要证据，语言是否符合要求。
- 可靠性：严格 JSON 成功率、修复后成功率、失败与重试次数。

标准答案由人依据输入事实定义；OpenAI 与 Kimi 的结果是对照，不能自动当真值。

## 测速方法

- 相同机器、网络、输入、输出语言和测试时间段，交替或随机顺序运行，避免把单一时段波动归因于模型。
- 明确记录模型 ID、思考档位、输出上限、prompt/schema/评分策略版本。供应商参数不强行同名，选择适合结构化任务的低耗时配置并如实披露。
- 当前记录每次请求到完整响应时间、CLI 耗时及脚本测得的进程 wall time，尚未细分解析/校验时间。不用首 token 时间代替最终 JSON 完成时间。
- 首轮比较关闭应用结果缓存；供应商 prompt 缓存命中由 usage 如实记录。热缓存另测，不和冷启动混为一谈。
- 每案例每路径计划重复 3 次，记录原始值、中位数和范围；小样本不宣称稳定生产 p95。连接复用和冷连接状态也应一致或分别报告。
- 所有失败、重试及其耗时计入完成率和任务成本；有界并发，单任务延迟测试不与高并发吞吐混测。

## 成本与选择规则

累计整个任务输入、缓存、输出和可计费推理 token，按模型对应日期/站点/币种/时段价格计算；避免对已计入 output 的 reasoning token 重复计费。供应商未返回完整 usage 时标记估算不完整。

选择顺序：先排除有严重事实捏造、证据错配或核心契约失败的方案，再看质量差异、真实速度和成功任务成本。初步将同一案例重复测量的波动范围与结果等级一起判断是否“接近”，不靠主观总印象或一个微小平均差决定胜负。差异明显时给出取舍；表现接近时采用 DeepSeek。确切量化阈值应在看最终保留样例结果前固定并记录。

评测记录存放输入 ID、配置、检查结果、输出摘要、每阶段 usage/耗时与错误；合成结果可供发布，真实候选内容保留本地。最终表格应明确样本数、缺测路径和局限。

## 当前缺项

已有评测脚本、合成 PDF 与 12 案例；缺实际 API 结果、模型可用性验证、人工质量评分和独立保留集。需要用户为本任务提供各供应商 key；不读取其他项目凭据。

## 执行入口与产物

`scripts/evaluate.py` 默认 dry-run；`--execute --out <新目录>` 才运行。默认四路径、每案例三次、seed=20260920 打乱顺序、不启用应用缓存；共 144 次 CLI 运行。首次应使用 `--limit 2 --repeats 1 --routes gemini deepseek` 冒烟确认可用。模型 ID 显式固定，覆盖可能污染比较的模型/端点环境变量。脚本仅继承所需环境，不读取 .env。

每次保存 result.json、stats.json、stderr.log、review.json；runs.jsonl 逐条追加以保留中断前进度，summary.json 包含完成率、含失败的 wall time 中位数/范围、已观察费用及完整性标记。无自动质量分、无自动胜者。review.json 按案例原文填写事实错误、遗漏、无证据判断与报告质量。

费用缺项或重试不完整时不把观察到的金额当作完整成本。延迟报告须同时列失败率，不能因快速失败而选出错误赢家。mock 运行与真实路径禁止混在一批汇总。

初步选择门槛（真实结果前固定）：核心契约/凭空捏造不得存在未修复错误；报告语言正确，遗漏和证据错配必须逐项解释。质量接近要求两方案在同一批案例中没有一方独有的严重事实错误、逐项状态一致率至少 95%；速度接近暂按成功案例配对中位数差不超过 20%，并报告重复试验的波动。满足这些条件时按完整估算成本优先 DeepSeek；未满足则呈现具体差异，不自动决策。小样本阈值用于本次工程选择，不代表统计显著性。
