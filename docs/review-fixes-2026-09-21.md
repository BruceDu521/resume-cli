# 评分 review 修复（2026-09-21）

默认 single，保留显式 `--pipeline jev`。本轮聚焦默认路径，没有追加批量评测。

## 已改行为

- Candidate 不再要求结构化姓名、技能、学历等字段逐字出现在原文，允许合理规范化；独立核验每条原文引用，不维护同义词特例。
- single 模型只输出 matches、comment、interview_questions。每项包含 JD 要求、类别、必需性、状态和引用数组；内部 ID 由代码生成，复用本地评分，不要求模型生成 Resume 或独立 Facts/Job/Judgments。
- 每项要求支持多处不连续证据，各处分别校验范围与原文。最终 JSON 使用 evidence_ids / evidences；旧 Jev 仍使用标量证据字段及单条选择逻辑，本轮未增强该可选路径。
- 移除 24 项 JD 和 16 行引用上限；无关的个人字段提取不再阻断默认评分。没有相关证据时允许全部 unknown，而不是因空事实列表失败。

## 验证与边界

全包离线 race 单测、vet 通过。新增回归覆盖 golang/Go 规范化、同一要求两处不连续引用、30 项要求全部保留、17 行引用有效、伪造引文拒绝，以及全部 unknown。它们验证程序行为，不衡量模型语义准确率，也不能保证模型不遗漏 JD。

随后仅用授权真实简历执行一次 Gemini 默认评分：一次调用，无纠正；模型调用 6.912 秒、CLI 6.958 秒、评测脚本墙钟 9.235 秒；输入 2,808 token、输出 1,327 token。5 项要求全部保留，实际输出多处引用，Rust 标记为 unknown。评论额外推断了“全日制”，原文不能确认；这是未解决的语义问题，不因结构和引用校验通过而忽略。真实材料与结果只保留本地，不提交 Git。

## 保留的限制及原因

- PDF 20 MiB、提取文本 160 KiB、JD 64 KiB、序列化模型输入 200 KiB、响应 2 MiB：控制本地内存及请求开销，超限报错，不截断业务内容。
- HTTP 每次 60 秒、CLI 默认 90 秒（可配置至 10 分钟）；最多一次格式/领域纠正，暂时 HTTP 错误最多三次尝试：限制等待及调用成本。
- 供应商输出 token 预算仍有限（适配器 12k/16k）；截断响应拒绝，不当作完整成功结果。
- 可选 Jev 保留本地状态 48 KiB、请求 96 KiB 预算；这是保守资源保护，不宣称官方上下文上限，超限明确报错。
- JSON 深度 64 用于解析器保护，与事实条数无关；非空 JD 要求、有效状态、引用 ID/顺序/原文一致性仍校验。

来源存在不能证明证据充分。复杂版面顺序、技能归纳、证据选择、评论推断仍需人工复核；本轮没有重新实测 Jev、Kimi、DeepSeek 或 OpenAI。
